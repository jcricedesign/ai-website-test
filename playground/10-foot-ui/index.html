10' UI

Exploring interfaces designed to be used from across the room.

What began as putting my portfolio on a television became an experiment in designing for a very different interaction distance. A conventional website worked, but it wasn't enough: type, composition, navigation, feedback, and input all needed to behave differently at ten feet.

01

Multiple inputs, one interface.

The display can be controlled by voice, a phone, mouse or keyboard, or conventional links. No single input method is required for the overall experience, allowing people to use whichever interaction feels most natural or available.

02

Designing for the room.

Display Mode adapts the portfolio for a large television rather than simply enlarging the desktop site. Layouts become wider, visual hierarchy changes, navigation becomes more presentation-oriented, and an animated screensaver turns the display into something that can remain comfortably present in a space.

03

Atlas.

A local voice interface provides simple spatial and semantic commands: next, back, home, career, playground, screensaver. Voice isn't intended to replace the interface—it is another way into it.

04

Built to recover.

The display, phone control, and voice system run as independent services. We deliberately killed individual components during testing: the display can restart itself, voice can disappear without disabling phone control, and services can reconnect without rebooting the system.

v1.0

A portfolio display built to stay running.

The result is a Raspberry Pi-powered portfolio display that boots directly into the experience, can run unattended, supports multiple simultaneous forms of interaction, and recovers from common failures automatically.

Accessibility isn't necessarily one perfect input method.

It can also mean building a system that accepts different people, devices, distances, and ways of interacting.
